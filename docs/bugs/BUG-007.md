# BUG-007 : Un caractère spécial dans la recherche provoque un 500 avec trace de pile

| Champ | Valeur |
|---|---|
| **Famille** | Robustesse |
| **Sévérité** | Moyenne (S3) |
| **Priorité** | Haute (P2) |
| **Exigence violée** | AC-04.3, SEC-05, « une erreur 500 ne contient jamais de trace de pile » |
| **Environnement** | minishop-app, `BUGS=BUG-007` ou `BUGS=on`, Node.js 22, Chromium (Playwright) |
| **Statut** | Ouvert (défaut volontaire, voir `minishop-app`) |

## Étapes de reproduction

1. Appeler `GET /api/products?q=(` (même résultat avec `[` ou `*`).
   ```bash
   curl -i 'http://localhost:3000/api/products?q=('
   ```

## Résultat attendu

`200` avec une liste vide : le texte est traité littéralement (`count: 0`).

## Résultat obtenu

`500 Internal Server Error` et un champ `stack` dans le corps de la réponse : `SyntaxError: Invalid regular expression: /(/i: Unterminated group`, avec les chemins de fichiers du serveur. Cause : le texte saisi est utilisé comme expression régulière. Dans l'interface, la recherche ne renvoie aucun résultat utile.

## Impact

Fuite d'informations internes (structure des fichiers, bibliothèques) utile à un attaquant ; déni de service ciblé d'une fonction (une expression régulière fournie par l'utilisateur peut aussi être coûteuse : ReDoS).

## Tests automatisés qui le détectent

- `tests/api/products.api.spec.ts` : une série de caractères spéciaux sans erreur 500 ; aucune trace de pile dans une erreur interne
- `tests/e2e/products.spec.ts` : un caractère spécial ne casse pas la page

Ces tests utilisent `expectBug('BUG-007')` : en mode `BUGS=on` leur échec est attendu et rapporté comme réussi ; en mode `BUGS=off` ils doivent passer.
