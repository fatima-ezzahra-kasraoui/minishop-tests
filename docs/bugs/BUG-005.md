# BUG-005 : La lecture d'un panier est possible sans jeton

| Champ | Valeur |
|---|---|
| **Famille** | Authentification |
| **Sévérité** | Haute (S2) |
| **Priorité** | Haute (P1) |
| **Exigence violée** | AC-06.2, AC-06.4, SEC-02 |
| **Environnement** | minishop-app, `BUGS=BUG-005` ou `BUGS=on`, Node.js 22, Chromium (Playwright) |
| **Statut** | Ouvert (défaut volontaire, voir `minishop-app`) |

## Étapes de reproduction

1. Appeler `GET /api/basket/<id>` **sans** en-tête `Authorization` :
   ```bash
   curl -i http://localhost:3000/api/basket/1
   ```
2. Variante : envoyer un jeton falsifié (`Authorization: Bearer abc.def.ghi`).

## Résultat attendu

`401 {"code":"AUTH_REQUIRED"}` sans jeton, `401 {"code":"INVALID_TOKEN"}` avec un jeton invalide.

## Résultat obtenu

`200 OK` avec le contenu du panier, sans aucune authentification.

## Impact

Toute personne qui atteint l'API, même non inscrite, lit les paniers. Plus grave que BUG-004 car aucun compte n'est requis. Classe OWASP : Identification and Authentication Failures.
