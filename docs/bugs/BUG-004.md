# BUG-004 : Un utilisateur peut lire le panier d'un autre (IDOR)

| Champ | Valeur |
|---|---|
| **Famille** | Contrôle d'accès |
| **Sévérité** | Haute (S2) |
| **Priorité** | Haute (P1) |
| **Exigence violée** | AC-06.3, « panier visible uniquement par son propriétaire » |
| **Environnement** | minishop-app, `BUGS=BUG-004` ou `BUGS=on`, Node.js 22, Chromium (Playwright) |
| **Statut** | Ouvert (défaut volontaire, voir `minishop-app`) |

## Étapes de reproduction

1. Créer deux comptes, Alice et Bob, et se connecter avec chacun pour obtenir deux jetons.
2. Avec le jeton d'Alice, ajouter un produit à son panier (`POST /api/basket/items`).
3. Avec le jeton **de Bob**, appeler `GET /api/basket/<id d'Alice>`.

## Résultat attendu

`403 {"code":"FORBIDDEN","message":"Accès refusé."}`.

## Résultat obtenu

`200 OK` avec le contenu complet du panier d'Alice. Les identifiants étant séquentiels, essayer les identifiants voisins suffit pour énumérer les paniers de tous les utilisateurs.

## Impact

Fuite de données personnelles entre utilisateurs authentifiés, à grande échelle (énumération). Classe OWASP : Broken Access Control.

## Tests automatisés qui le détectent

- `tests/security/access-control.spec.ts` : lecture du panier d'autrui (403), contenu non divulgué, énumération des identifiants voisins

Ces tests utilisent `expectBug('BUG-004')` : en mode `BUGS=on` leur échec est attendu et rapporté comme réussi ; en mode `BUGS=off` ils doivent passer.
